## 1) Discord Server Owner / Moderator

### A) Short DM
```
“Hey <ModName>, I’ve been in this server for <N months/years> and noticed <specific pain or missing feature>. I like building impactful side projects for fun and for my resume. I can add <feature or fix bug> and share the full source code back for free. **Would you be interested?**”
```

### B) Slightly Longer DM/Email
```
Subject: Tiny <feature/bugfix> for <server_name> — shipped in <timeframe>

Hi <Name>, I’m <Your Name>, active in <server_name>. I saw <specific pain> affecting <who/how often>. 
I can prototype <one clear outcome> (e.g., “/rank shows last 7 days, with <extra>”) and set up basic metrics (calls/day, unique users).
I’ll PR the source, write handover docs, and remain available to test. 
Would you be open to this?
```

### C) Follow-up (2–3 days later)
```
Hi <Name> — quick nudge on the <feature/bugfix> idea for <server_name>. 
Happy to scope it smaller (<minimal version>) or pair with a mod to test. Still useful?
```

## 2) Open Source (GitHub Issues & PRs)

### A) Claiming an Issue
```
Comment on issue:
Hi! I can take this. Plan: <very short plan: 1–3 steps>. 
ETA <date>. Will add tests for <X> and update docs.
```

### B) First PR Message
```
Title: <component>: <concise change>
Body:
- Problem: <current behavior / pain>
- Change: <what you did>
- Tests: <unit/integration notes>
- Docs: <link or README section>
- Impact: <faster by X% / reduces steps from A→B / fixes #<issue_id>>
```

### C) Maintainer Nudge
```
Hi <Maintainer>, following up on PR <#>. 
Happy to adjust to your style guide or split into smaller PRs. 
Any feedback blockers I can address?
```
